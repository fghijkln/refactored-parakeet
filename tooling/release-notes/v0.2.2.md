Parakeet v0.2.2 — deep customization of [dsh-Go](https://github.com/ccch1mneyyy/dsh-go) by [ccch1mneyyy](https://github.com/ccch1mneyyy) (AGPL-3.0, upstream ccch1mneyyy/dsh-Go@cf2f7c8; changes listed in PARAKEET_NOTICE.md). Not an official DSH Go build.

Changes in 0.2.2: **Root permission.** Settings › System permissions has a new Root item. Once you grant it (KernelSU; Magisk works too), the AI agent is the device's root user: every shell command it runs executes as uid 0 through su, with no per-command confirmation. Brick-risk operations still ask you once, every time: writing or flashing partitions (/dev/block, fastboot, dd), mounting read-write or writing system partitions (/system, /vendor, /product, /system_ext, /odm, boot, recovery, vbmeta, super), formatting or wiping /data and /metadata, and partition-table / device-mapper edits. The engine itself keeps the app's uid (only the agent's commands cross su, with HOME/TMPDIR/PATH/LD_LIBRARY_PATH/OpenSSL settings carried over); turning Root off takes effect on the next command. The emulator smoke now runs a real agent turn with Root granted (uid 0) and checks that a brick-risk command is stopped at the confirmation.
